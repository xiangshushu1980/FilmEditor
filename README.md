## 使用顺序

1. 新建短片，从 Reference 勾选实体导入。自动下载当前确认的主形象、多视图和基础声音；不把历史确认版本当当前定稿。缺失字段和关系按来源保留，不能补造。
2. 在“接口与参数”设置 OpenAI 兼容 `/v1` 基址、模型名、temperature、目标总时长及分辨率。API key 仅从服务器 `.env` 读取，不发送给浏览器、不写进项目。无 key 的本地兼容接口也可用。应用直接调用 `/chat/completions`，不使用 Agent、Skill 或导演工具。
3. 填剧情并保存，点击“生成剧本与对白”。请求立即建立任务，不锁住页面等待全套结果。完成后先查看/编辑剧本与对白总稿，保存后点击“确认剧本与对白”。
4. 点击“生成拍摄本”。生成各镜动作、构图、时长、引用和逐镜对白，不生成长提示词；在右栏编辑并保存，审阅后点击“确认拍摄本”。也可手写剧本并添加镜头逐阶段确认。
5. 在右栏“提示词”页为每镜点击“生成／重试本镜提示词”，结果独立保存且可编辑。过期但仍适用的旧提示词可点击“复核当前提示词”。完成后点击“批准剧本与拍摄本”，记录人工审核人 Sean、时间和输入哈希，校验六段格式、引用及原话。前序修改会使后续确认失效，但保留旧内容；详见 [阶段状态、版本与恢复](STAGED_PLANNING.md)。
6. 启用 GPU 的授权宿主可逐镜“生成新候选”。适配器检查共享队列与资源占用、取得 `gpu:0` 租约、每30秒心跳/采样显存、完成后 observe/release。固定使用已有实验的 Ref2VA INT8 + Ref2VA PDD 8步 + Sage、24fps，不换模型路线、不释放共享模型、不重启实例。
7. 在候选历史中播放并选用。“重试原输入”产生有 parentId 的新候选；修改 prompt/seed 后生成的是新分支。旧视频、输入、prompt、seed、模型、快照、审核、workflow、promptId、执行历史和错误均保留。原输入过期时不能选用或按原输入重试。

生成期间顶部持续显示项目/镜头、资源检查、素材准备、模型处理、采样、解码、归档或释放资源等状态及已用时间。通过 ComfyUI WebSocket 接收当前任务的实际步骤进度；步骤 `3/8` 表示当前采样/节点进度，不是整片完成比例。没有数值进度的阶段显示等待条，连接断开后继续通过历史轮询获取结果。候选卡也保留最后状态。页面每2秒更新，按钮下方解释不可点击的原因（未保存、未审核、GPU关闭、已有生成或等待资源释放）；完成/失败并释放生成锁后给出提示。不自动重提交候选，也不提供影响共享队列的取消操作。
8. 调整镜头顺序并“合成选定镜头”。FFmpeg CPU 将各片规格和音轨统一，再拼接；缺音轨时补静音。按**实际媒体时长**合成，不用请求时长截断片尾；旧成片保留，可播放和下载。

## Reference 修订与快照

“检查更新”对比实体 `sourceRevision` 内容哈希；服务错误为请求失败，来源消失单独标记，均不会覆盖项目。点击“使用最新修订”才创建新快照。完整原 manifest 不改写；新增本地映射保存下载后的 blob 哈希、来源修订和 MIME。manifest 与每个文件均校验 SHA-256。

新修订只替换变化实体的当前快照引用；相关镜头标记 stale、取消旧候选选择、撤销审核，成片标记 stale。原图片选择按角色映射到新定稿；图片数或引用职责变化时必须人工检查标签。声音更新会清空人工核对台词。镜头在基于新快照重新生成并选定后才清除 stale；成片在重新合成后才清除。所有旧快照、素材、候选、成片仍可追溯。

原接口返回的 `omissions`、`missingCapabilities`、`missingFields`、prompts 和 relations 原样保留。仅保存当前明确选择的确认素材字节，不读取 Reference 内部磁盘路径。当前声色情绪样音或音效能力不存在时，不猜造资产。

## 声音与 Ref2VA

默认镜头对白由 H3 生成；导入的基础声音可听审，**不默认作为音色参考端口**。想完整复用已有音频时，在镜头高级区选“锁定已有音频”：听音频、输入人工核对原话、设置与源录音一致的时长（±0.2秒）、让逐镜对白与原话逐字相同，并修改 prompt 为 `audio reuse`/`fully_copy`。链路使用 **NativeAudioLock**，不会当作普通 `ref_audio`。

提示词契约来自 [.pi H3 skill](../.pi/skills/h3-prompt-writing/SKILL.md)、[Ref2VA官方格式](../.pi/skills/h3-prompt-writing/references/ref-en.txt)与[项目规则17](../docs/17_h3_prompt_writing_rules.md)。适配器和参数参照[已验证实验](../experiments/ai_film_editor_flow_20261003/README.md)及其 manifest。已测 H3 输出存在时长扩展（4秒请求实际4.458秒），此应用保留实际媒体并在合成时用 ffprobe 时长；NativeAudioLock 不代表已验收逐样本音频一致。

## 数据与恢复

默认存储 `film-editor/.data/film.sqlite` + `.data/blobs/<sha256>`，可用 `FILM_DATA_DIR` 指定持久位置。重启应用保留项目与全部媒体；SQLite WAL/事务和 revision 校验保护并发编辑，SQL trigger 禁止修改/删除快照和成片、禁止改候选原输入。候选状态与追加事件保留执行演进，项目 JSON 导出可审查；JSON **不包含素材字节**。

分阶段 LLM 编写和 CPU 合成也保存独立任务记录：输入修订/参数/快照引用、开始与结束时间、成功或错误状态。同项目创作生成任务执行期间拒绝另一个阶段生成请求；迟到的生成结果遇到输入修订冲突时保留到任务记录，不覆盖当前内容。重启后仍在执行的记录标记为“已中断”，保留历史并等待手动重试，不自动重复付费请求。LLM 请求上限为 10 分钟。拍摄本上方“任务记录”可查看这些状态和原始结果，“创作版本历史”可查看完整历史产物。

剧情参与候选输入哈希；修改剧情会使旧候选失效。2026-10-03 本轮补齐这一字段后，此前版本产生的候选会按旧输入失效，需要重新生成。

备份须保存整个数据目录。停编辑器后复制整个 `.data`，或用 SQLite 在线备份再复制 blobs；不要只拷贝运行中 `film.sqlite` 忽略 WAL。不提供自动垃圾回收、删除或覆盖旧版本。

服务重启不会自动重新提交 GPU 工作：有持久化 promptId 的候选尝试恢复轮询并归档结果，没有 promptId 的输入保留并标为失败/待核查。提交网络结果不明时保持本地生成锁，等待共享队列排空后才允许新候选。请在重新生成前核对历史；恢复不构成“再次点击生成”。本机多进程端口冲突自然拒绝第二编辑器实例；不要将同一 data dir 配置给不同端口的多个进程。

下载产物先存本项目并计算哈希；`COMFY_OUTPUT_DIR` 默认 `/home/sean/projects/ComfyUI/output`，然后只删除当前候选专属 `video/sean_film_editor/<candidateId>/clip*.mp4` 中经字节哈希再次核对的确切文件。清理失败保留事件，需人工整理；不会扫描或删除其他产物。输入上传也使用候选唯一前缀。此数据目录是应用项目库；研究实验继续单独归档到 experiments。

## API 和限制

- `GET/POST /api/projects`；`GET/PATCH /api/projects/:id`，修改请求需 revision。
- `GET /api/reference/entities`；`POST /api/projects/:id/import`（entityIds，可选assetIds）；`GET .../reference-changes`；`POST .../use-latest`。
- `POST .../plan`、`POST .../shots`、`PUT .../shots/:shotId`、`POST .../shot-order`、`POST .../approve`。
- `POST .../candidates`（shotId，parentId，retryExact）；`POST .../select`（candidateId）；`POST .../assemble`。
- `GET .../inventory`、`GET .../export`；`GET .../media/:hash`（项目归属校验、Range、正确 MIME）。

仅监听 loopback，检查 Host/Origin，无公网鉴权或部署入口。长 LLM/合成请求在服务端执行；外部 provider 配置由可信本机用户掌握。MVP 不包含镜头删除、字幕、配乐轨、人物动作白模、Agent/Skill UI、自动导演、发布平台、GPU取消（避免中断共享队列）或精确口型/音频保真 QC。修改输入后保留历史，审核和生成必须人工触发。

交付验证：`npm run build` 生产构建通过；未新增或运行测试，未提交 GPU 作业。真实 LLM、GPU预览与成片链路需要用户提供接口配置并进行产品验收，本次不声称已实跑验证。

### [Sean] 视频反馈与提示词修订

镜头状态按当前输入对应的候选计算：生成中、已生成待选片、已选定、需重新生成、生成失败、需生成；成功视频不自动选用。旧输入视频保留，可观看但不能选用或按原输入重试。

在「候选与历史」点击「描述问题并修订提示词」，分别填写实际问题与期望效果（朝向应描述身体、视线和空间参照）。修订任务只保存提案，不覆盖当前内容；查看修改说明、原提示词和可编辑修订稿后点击采用。采用通过现有校验，保存不可变创作版本和反馈审计，撤销视频生成审核和当前选片，旧视频保留。重新批准后可生成新候选。项目版本改变会拒绝采用旧稿，需重新提交；失败或重启中断保留记录，不自动重请求。模型只收到文字反馈及原候选提示词，没有自动观看视频。

当前模型请求使用项目内提炼的 Ref2VA 规则摘要，而非整份官方 skill 文档；固定规则位于 system 前缀，项目及反馈位于 user 消息。缓存由提供方管理，不复用过期生成结果。响应 provenance 保存原始 usage 和兼容 OpenAI/DeepSeek 的 cachedTokens，修订稿显示命中量；未返回字段显示「接口未返回」。

### [Sean] 全片空间与方位修订

在拍摄本下方点击「统一空间并修订全部提示词」。模型使用当前实体快照中的 description、appearance、公开导出的扩展信息及当前素材关联的来源 prompts（包括 text/effectiveText），同时读取完整拍摄本、旧提示词和逐镜 Picture 绑定。来源提示词代表生成意图，不能替代实际看图；已确认场景事实优先，缺失或冲突列为待确认事项。新实体字段只要进入公开 manifest 就能作为 exportedFacts 传入，不预设实体侧的新 schema。

全片修订是可恢复的 spatial 后台 job，输出共用空间说明、逐镜开始/结束物理状态、前镜衔接、构图/连续性、完整 Ref2VA 提示词和修改说明。可审阅编辑，未解决事项阻止采用。采用须原始项目 revision 匹配，校验全部镜头的完整性/顺序/引用/对白和提示词格式，原子保存创作版本、空间计划、反馈审计及采用记录。剧情、动作、运镜、台词、镜头 ID/顺序、时长、种子和参考列表均不由提案改写。构图和连续性修改后须重新确认拍摄本，随后批准视频生成。

空间计划参与候选输入哈希和提示词来源哈希，采用后所有旧视频/成片保留但过期。实体、剧情、镜头顺序或动作/构图/连续性等输入变化会使空间计划过期，需重新生成全片提案；历史计划仅作修订参考。后续单镜生成及视频反馈修订自动携带已采用空间计划和全片镜头状态，不把前镜视频视为自动可见上下文。格式与依赖校验不等于视觉连续性验收，站位逻辑和实际生成效果仍须审阅。

实体更新后的顺序：检查来源 → 使用最新修订 → 确认剧本 → 统一空间并修订全部提示词 → 审阅/采用 → 确认拍摄本 → 批准生成 → 逐镜视频生成/选片/合成。空间修订失败或服务中断保留任务记录，不自动重复请求；可重新提交，旧提案和现有创作不覆盖。

### [Sean] 修订稿报错后的操作

打开「审阅修订稿」后，红色提示定位到各镜；报错镜头自动展开，「定位并编辑提示词」跳到完整提示词编辑框。修改后点击「重新校验当前稿」，结果替换生成时的旧警告。格式校验通过且待确认事项清空后才能采用。

不想手工修改时，在「回答待确认事项／希望 AI 修改的内容」逐项回答或提出修订要求，然后点击「根据回答与当前稿让 AI 继续修订」。服务端同时传入当前编辑稿、回答和重新计算的校验错误，创建新的 spatial job；新稿仍需审阅采用，旧稿和原始模型输出保留。未回答的问题不得自动删除，动作／对白／时长等仍服从已确认拍摄本。需要改变动作或时长时先修改、保存并确认拍摄本，然后基于当前拍摄本重新生成。

「保存审阅草稿」保存 job.reviewDraft 和当前校验结果，关闭、刷新或服务重启后再打开该稿可继续编辑；不增加项目 revision、不改写拍摄本、不撤销当前审核。明确采用才走既有不可变创作版本与审核失效流程。历史已采用稿和项目版本变化后的旧稿显示为只读，并提供「基于当前拍摄本重新生成」；界面同时显示提案和项目版本。审阅／保存／校验请求中的错误直接显示在弹窗内。

### [Sean] 查看拍摄本和当前阻塞步骤

「查看并确认拍摄本」按顺序展示已保存镜头的动作／人物安排、构图、运镜、连续性、对白、实体与Picture引用顺序，支持跳转到对应镜头编辑；提示词仍在右栏单独编辑。完整拍摄本弹窗不提交生成，不自动确认；未保存的编辑有提示。镜头列表放在拍摄本区域，避免与提示词阶段混淆。缺少动作、构图、运镜或参考图的镜头会提示名称和缺失项，补齐保存后才可确认。

页面顶部「当前流程状态」按现有持久化状态提供下一步入口：保存修改／等待文本任务／确认剧本／生成与确认拍摄本／修订过期空间／补齐提示词／生成前批准／启用配置或等待生成。任务摘要提供inputRevision，当前可审阅的空间提案按输入版本匹配，不使用任务完成时的版本代替。阶段完成与格式校验区分：批准仍执行服务端完整校验。视频按钮显示具体前序阻塞原因；空间过期时不允许提交单镜提示词生成。

### [Sean] 镜头增删与审阅确认

拍摄本区域的「查看并确认拍摄本」先打开整体审阅，不直接写入确认；只有完整拍摄本弹窗内的「确认这份拍摄本」提交确认。缺失安排或未保存编辑仍阻止确认。

「添加镜头」在末尾追加；卡片的＋或完整拍摄本内的「在此镜后插入」调用既有afterId契约按位置插入，新增后直接进入该镜编辑。每片最多40镜。卡片「删除」或完整拍摄本「删除此镜」先展示具体镜头和影响，取消不修改，明确删除后从当前拍摄本移除；若删的是正在编辑镜头，选择相邻镜头；从完整拍摄本删除后返回更新后的整体审阅。

删除接口以revision校验并原子保存前后创作版本、删除审计和镜头原文，保留所有视频候选／素材／旧成片；清理该镜提示词确认映射，撤销生成批准、标记成片过期，镜头集合变化使拍摄本重新待确认及已有空间计划过期。编写／合成进行中及该镜头视频生成／恢复中拒绝删除。可以删到零镜，再重新添加，不删除实体快照。
