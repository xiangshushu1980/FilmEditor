## 安装与启动

```bash
cd /home/sean/projects/FilmEditor
npm ci
cp .env.example .env
# 编辑 .env 的 LLM_BASE_URL、LLM_MODEL、LLM_API_KEY。
npm run build
npm start
```

打开 **http://127.0.0.1:4190**。开发模式为 `npm run dev`，Vite 中间件和 API 共用4190，不另开前端端口。需要 Node >=24、系统 FFmpeg/ffprobe；`hive-resource` 只有开启 GPU 预览时才需要。应用不会启动或重启 Reference/ComfyUI；由现有服务管理方式提供 Reference 4188、ComfyUI 8188。

2026-10-03 续作已启动独立的 systemd 用户服务 `sean-film-editor.service`，GPU 关闭。服务状态与停止命令：

```bash
systemctl --user status sean-film-editor.service
systemctl --user stop sean-film-editor.service
```

该服务为本次启动的 transient unit；系统重启后使用上面的 `npm start`，或在项目目录中重新托管：

```bash
systemd-run --user --unit=sean-film-editor --description='Sean Film Editor' \
  --working-directory="$PWD" --setenv=FILM_ENABLE_GPU=0 \
  "$(realpath "$(command -v node)")" --env-file-if-exists=.env server/index.mjs
```

## 使用顺序

1. 新建短片，从 Reference 勾选实体导入。自动下载当前确认的主形象、多视图和基础声音；不把历史确认版本当当前定稿。缺失字段和关系按来源保留，不能补造。
2. 在“接口与参数”设置 OpenAI 兼容 `/v1` 基址、模型名、temperature、目标总时长及分辨率。API key 仅从服务器 `.env` 读取，不发送给浏览器、不写进项目。无 key 的本地兼容接口也可用。固定文字工作流直接调用 `/chat/completions`；可展开「制作助手」使用独立 PI 会话调用这些流程。
3. 在「1 剧本与对白」填写剧情，点击「生成剧本与对白」。内容可直接查看、编辑。点击下一阶段生成时会先保存当前编辑，再使用该版本生成，不需要另外确认。
4. 在「2 拍摄本」点击「生成拍摄本」。本区域按「全片空间与站位 → 有序镜头安排 → 对应逐镜提示词」阅读；镜头的动作、构图、运镜、对白和图片引用可在右栏编辑。可添加、插入或删除镜头。
5. 在同一拍摄本区域「统一空间并修订全部提示词」，查看共用空间与逐镜开始／结束状态；审阅修订稿、解决问题后采用。已采用的共用空间可直接编辑。也可在右栏逐镜生成或修改提示词。修改前序内容会标记依赖内容过期，旧内容和旧视频保留。
6. 在「3 视频生成与结果调整」选择镜头，点击「生成新候选」。服务端保存并校验当前镜头输入，不再要求额外的全片批准；其他未完成镜头不阻止此镜生成。过期空间、过期提示词、缺少引用或格式不合格仍会阻止提交，并显示原因。GPU 需在授权宿主启用；适配器使用共享队列与资源租约，不启动或重启 ComfyUI。
7. 在候选历史中播放并选用；可描述实际问题和期望效果，让模型提出提示词修订。修改后重新生成保留旧候选、输入、媒体和版本。
生成期间顶部持续显示项目/镜头、资源检查、素材准备、模型处理、采样、解码、归档或释放资源等状态及已用时间。通过 ComfyUI WebSocket 接收当前任务的实际步骤进度；步骤 `3/8` 表示当前采样/节点进度，不是整片完成比例。没有数值进度的阶段显示等待条，连接断开后继续通过历史轮询获取结果。候选卡也保留最后状态。页面每2秒更新，按钮下方解释不可点击的原因（输入缺失或过期、GPU关闭、已有生成或等待资源释放）；完成/失败并释放生成锁后给出提示。不自动重提交候选，也不提供影响共享队列的取消操作。
8. 调整镜头顺序并“合成选定镜头”。FFmpeg CPU 将各片规格和音轨统一，再拼接；缺音轨时补静音。按**实际媒体时长**合成，不用请求时长截断片尾；旧成片保留，可播放和下载。

## Reference 修订与快照

“检查更新”对比实体 `sourceRevision` 内容哈希；服务错误为请求失败，来源消失单独标记，均不会覆盖项目。点击“使用最新修订”才创建新快照。完整原 manifest 不改写；新增本地映射保存下载后的 blob 哈希、来源修订和 MIME。manifest 与每个文件均校验 SHA-256。

新修订只替换变化实体的当前快照引用；相关镜头标记 stale、取消旧候选选择、撤销审核，成片标记 stale。原图片选择按角色映射到新定稿；图片数或引用职责变化时必须人工检查标签。声音更新会清空人工核对台词。镜头在基于新快照重新生成并选定后才清除 stale；成片在重新合成后才清除。所有旧快照、素材、候选、成片仍可追溯。

原接口返回的 `omissions`、`missingCapabilities`、`missingFields`、prompts 和 relations 原样保留。仅保存当前明确选择的确认素材字节，不读取 Reference 内部磁盘路径。当前声色情绪样音或音效能力不存在时，不猜造资产。

## 声音与 Ref2VA

默认镜头对白由 H3 生成。有对白且未锁定整段音频时，系统自动将说话实体当前唯一的基础声音接为音色参考，并将具体 `<Audio N>` 与全片稳定说话者 ID 写入提示词上下文；每镜最多三个独立音色参考。派生角色通过当前「派生自」关系沿用基础角色声音，关系循环或多个基础来源会阻止提交。缺少基础声音时不会补造素材；已绑定端口也不代表音色效果已验收，仍需听审。

想完整复用已有音频时，在镜头高级区选“锁定已有音频”：听音频、输入人工核对原话、设置与源录音一致的时长（±0.2秒）、让逐镜对白与原话逐字相同，并修改 prompt 为 `audio reuse`/`fully_copy`。链路使用 **NativeAudioLock**，不会当作普通 `ref_audio`，也不会同时自动加入说话者音色参考。

提示词契约来自 [.pi H3 skill](../.pi/skills/h3-prompt-writing/SKILL.md)、[Ref2VA官方格式](../.pi/skills/h3-prompt-writing/references/ref-en.txt)与[项目规则17](../docs/17_h3_prompt_writing_rules.md)。适配器和参数参照[已验证实验](../experiments/ai_film_editor_flow_20261003/README.md)及其 manifest。已测 H3 输出存在时长扩展（4秒请求实际4.458秒），此应用保留实际媒体并在合成时用 ffprobe 时长；NativeAudioLock 不代表已验收逐样本音频一致。

## 编辑器组件约定

- `src/RecordCard.jsx`：紧凑、可选中的条目卡；点整张卡选择记录并切换右侧详情。卡片只放标题、状态与少量索引信息，不重复右侧正文。
- `src/ExpandableRecordGroup.jsx`：折叠/展开一组历史卡片，适用于任务记录、创作版本及后续实体变更历史。
- 桌面三栏可拖动两根分隔条调整宽度（左/中、 中/右），本地记忆宽度；左栏仍可单独收起。窄屏改为单列并隐藏拖动条。
- 详情由右侧检查器展示；卡片动作使用图标/短标签、`aria-label` 和 `title`，不再添加“查看详情”链接。
- 常规按钮高 36px，次级轻按钮 30px；主要动作保留清楚的文字。选择态微光、主按钮悬停扫光、生成状态边缘流光参考 Hivemind 的 GlowBorder、ShimmerButton、BorderBeam，均支持减少动态效果偏好。Hivemind 的 Vue/Tailwind 组件不直接复制；资源仪表盘依赖 ECharts 且当前页面没有对应资源指标，因此不引入。
- 概况与统计采用紧凑分块布局；新增实体、历史或候选列表时复用以上卡片与分组组件。

## 数据与恢复

默认存储 `film-editor/.data/film.sqlite` + `.data/blobs/<sha256>`，可用 `FILM_DATA_DIR` 指定持久位置。重启应用保留项目与全部媒体；SQLite WAL/事务和 revision 校验保护并发编辑，SQL trigger 禁止修改/删除快照和成片、禁止改候选原输入。候选状态与追加事件保留执行演进，项目 JSON 导出可审查；JSON **不包含素材字节**。

分阶段 LLM 编写和 CPU 合成也保存独立任务记录：输入修订/参数/快照引用、开始与结束时间、成功或错误状态。同项目创作生成任务执行期间拒绝另一个阶段生成请求；迟到的生成结果遇到输入修订冲突时保留到任务记录，不覆盖当前内容。重启后仍在执行的记录标记为“已中断”，保留历史并等待手动重试，不自动重复付费请求。LLM 请求上限为 10 分钟。拍摄本上方“任务记录”可查看这些状态和原始结果，“创作版本历史”可查看完整历史产物。

剧情参与候选输入哈希；修改剧情会使旧候选失效。2026-10-03 本轮补齐这一字段后，此前版本产生的候选会按旧输入失效，需要重新生成。

备份须保存整个数据目录。停编辑器后复制整个 `.data`，或用 SQLite 在线备份再复制 blobs；不要只拷贝运行中 `film.sqlite` 忽略 WAL。不提供自动垃圾回收、删除或覆盖旧版本。

服务重启不会自动重新提交 GPU 工作：有持久化 promptId 的候选尝试恢复轮询并归档结果，没有 promptId 的输入保留并标为失败/待核查。提交网络结果不明时保持本地生成锁，等待共享队列排空后才允许新候选。请在重新生成前核对历史；恢复不构成“再次点击生成”。本机多进程端口冲突自然拒绝第二编辑器实例；不要将同一 data dir 配置给不同端口的多个进程。

下载产物先存本项目并计算哈希；`COMFY_OUTPUT_DIR` 默认 `/home/sean/projects/ComfyUI/output`，然后只删除当前候选专属 `video/sean_film_editor/<candidateId>/clip*.mp4` 中经字节哈希再次核对的确切文件。清理失败保留事件，需人工整理；不会扫描或删除其他产物。输入上传也使用候选唯一前缀。此数据目录是应用项目库；研究实验继续单独归档到 experiments。

## API 和限制

- `GET/POST /api/projects`；`GET/PATCH /api/projects/:id`，修改请求需 revision。
- `GET /api/reference/entities`；`POST /api/projects/:id/import`（entityIds，可选assetIds）；`GET .../reference-changes`；`POST .../use-latest`。
- `POST .../plan`、`POST .../shots`、`PUT .../shots/:shotId`、`POST .../shot-order`、`POST .../approve`。
- `POST .../candidates`（shotId，parentId，retryExact）；`POST .../select`（candidateId）；`POST .../assemble`。
- `GET .../inventory`、`GET .../export`；`GET .../media/:hash`（项目归属校验、Range、正确 MIME）。

仅监听 loopback，检查 Host/Origin，无公网鉴权或部署入口。长 LLM/合成请求在服务端执行；外部 provider 配置由可信本机用户掌握。MVP 不包含字幕、配乐轨、人物动作白模、发布到外部平台、GPU取消（避免中断共享队列）或精确口型/音频保真 QC。修改输入后保留历史；生成由用户逐阶段触发，服务端检查实际输入依赖。

交付验证：`npm run build` 生产构建通过；未新增或运行测试，未提交 GPU 作业。真实 LLM、GPU预览与成片链路需要用户提供接口配置并进行产品验收，本次不声称已实跑验证。

### [Sean] 视频反馈与提示词修订

镜头状态按当前输入对应的候选计算：生成中、已生成待选片、已选定、需重新生成、生成失败、需生成；成功视频不自动选用。旧输入视频保留，可观看但不能选用或按原输入重试。

在「候选与历史」点击「描述问题并修订提示词」，分别填写实际问题与期望效果（朝向应描述身体、视线和空间参照）。修订任务只保存提案，不覆盖当前内容；查看修改说明、原提示词和可编辑修订稿后点击采用。采用通过现有校验，保存不可变创作版本和反馈审计，撤销视频生成审核和当前选片，旧视频保留。采用后可使用当前内容生成新候选。项目版本改变会拒绝采用旧稿，需重新提交；失败或重启中断保留记录，不自动重请求。模型只收到文字反馈及原候选提示词，没有自动观看视频。

当前模型请求使用项目内提炼的 Ref2VA 规则摘要，而非整份官方 skill 文档；固定规则位于 system 前缀，项目及反馈位于 user 消息。缓存由提供方管理，不复用过期生成结果。响应 provenance 保存原始 usage 和兼容 OpenAI/DeepSeek 的 cachedTokens，修订稿显示命中量；未返回字段显示「接口未返回」。

### [Sean] 一键合成

所有镜头有当前有效视频时，可点击「选用最新候选并合成」；已选定的有效候选保留，未选片的镜头选用最新成功候选。旧输入视频不参与，任一镜头缺少有效视频时显示原因并拒绝合成。按钮及状态说明显示合成执行中；成功后成片可播放下载。媒体工具优先使用 FILM_FFMPEG_BIN / FILM_FFPROBE_BIN，再寻找 ~/.local/bin、/usr/bin 和 /usr/local/bin，避免服务 PATH 导致 ENOENT。

### [Sean] 全片空间与方位修订

在拍摄本下方点击「统一空间并修订全部提示词」。模型使用当前实体快照中的 description、appearance、公开导出的扩展信息及当前素材关联的来源 prompts（包括 text/effectiveText），同时读取完整拍摄本、旧提示词和逐镜 Picture 绑定。来源提示词代表生成意图，不能替代实际看图；已确认场景事实优先，缺失或冲突列为待确认事项。新实体字段只要进入公开 manifest 就能作为 exportedFacts 传入，不预设实体侧的新 schema。

全片修订是可恢复的 spatial 后台 job，输出共用空间说明、逐镜开始/结束物理状态、前镜衔接、构图/连续性、完整 Ref2VA 提示词和修改说明。可审阅编辑，未解决事项阻止采用。采用须原始项目 revision 匹配，校验全部镜头的完整性/顺序/引用/对白和提示词格式，原子保存创作版本、空间计划、反馈审计及采用记录。剧情、动作、运镜、台词、镜头 ID/顺序、时长、种子和参考列表均不由提案改写。采用后可逐镜生成视频；生成时使用已保存的当前拍摄本并执行校验。

空间计划参与候选输入哈希和提示词来源哈希，采用后所有旧视频/成片保留但过期。实体、剧情、镜头顺序或动作/构图/连续性等输入变化会使空间计划过期，需重新生成全片提案；历史计划仅作修订参考。后续单镜生成及视频反馈修订自动携带已采用空间计划和全片镜头状态，不把前镜视频视为自动可见上下文。格式与依赖校验不等于视觉连续性验收，站位逻辑和实际生成效果仍须审阅。

实体更新后的顺序：检查来源 → 使用最新修订 → 编辑剧本和拍摄本 → 统一空间并修订全部提示词 → 审阅/采用 → 逐镜视频生成/选片/合成。空间修订失败或服务中断保留任务记录，不自动重复请求；可重新提交，旧提案和现有创作不覆盖。

### [Sean] 修订稿报错后的操作

打开「审阅修订稿」后，红色提示定位到各镜；报错镜头自动展开，「定位并编辑提示词」跳到完整提示词编辑框。修改后点击「重新校验当前稿」，结果替换生成时的旧警告。格式校验通过且待确认事项清空后才能采用。

不想手工修改时，在「回答待确认事项／希望 AI 修改的内容」逐项回答或提出修订要求，然后点击「根据回答与当前稿让 AI 继续修订」。服务端同时传入当前编辑稿、回答和重新计算的校验错误，创建新的 spatial job；新稿仍需审阅采用，旧稿和原始模型输出保留。未回答的问题不得自动删除，动作／对白／时长等仍服从已确认拍摄本。需要改变动作或时长时先修改拍摄本，然后基于当前拍摄本重新生成。

「保存审阅草稿」保存 job.reviewDraft 和当前校验结果，关闭、刷新或服务重启后再打开该稿可继续编辑；不增加项目 revision、不改写拍摄本、不撤销当前审核。明确采用才走既有不可变创作版本与审核失效流程。历史已采用稿和项目版本变化后的旧稿显示为只读，并提供「基于当前拍摄本重新生成」；界面同时显示提案和项目版本。审阅／保存／校验请求中的错误直接显示在弹窗内。

### [Sean] 拍摄本与生成入口

主界面直接展示拍摄本，不另外弹出确认界面：先读共用空间与站位，再按顺序读逐镜动作、构图、运镜、连续性、对白、实体与 Picture 引用，随后查看对应提示词。右栏用于编辑选定镜头。

顶部「当前流程状态」依据内容和真实输入依赖提示下一步：等待任务、补齐剧情和实体、生成剧本或拍摄本、修订过期空间、补齐或更新提示词、启用 GPU 或生成视频。每次生成先保存当前编辑，使用保存返回的 revision；生成不会自动进入下一阶段。手写内容同样可作为下一阶段输入。任务与完整创作版本可查看。

「添加镜头」在末尾追加；卡片的＋在对应镜头后插入；最多40镜。删除先展示具体镜头和影响，取消不修改，删除后选择相邻镜头。服务端以 revision 校验并原子保留前后版本、删除审计和原镜头，所有旧候选、素材与旧成片保留。正在编写／合成及该镜视频生成／恢复时拒绝删除。镜头集合变化会使已有空间计划过期，需要按新拍摄本修订。

### [Sean] PI 制作助手

在主页面展开「制作助手」，可查询脱敏故障日志、提出可复用方法和程序修改，检查完整叙事与实体参与方式、跨镜位置和道具／服装衔接，或要求实际修订和生成。每轮先保存当前编辑。选择「仅讨论和检查」只读和提出建议；「允许文字生成与修订」可使用现有文字工作流并采用修订；「允许生成视频与合成」还可提交视频、观察候选帧、选片和合成。操作范围不代表自动执行所有阶段，仍以当轮要求为准。

助手使用 PI SDK 0.86.0 与独立应用目录 `.data/agent/`。配置该目录的 `auth.json`、`models.json`、可选 `preferences.json`，或设置 FILM_AGENT_AUTH_FILE / FILM_AGENT_MODELS_FILE；可用 FILM_AGENT_PROVIDER / FILM_AGENT_MODEL 限定模型。需要支持图片的已配置模型。目录建议700、凭据文件600，备份时按密钥资料处理，不能提交 Git。全局 Pi 配置和 Reference 不被修改。云端模型适合助手操作视频；本机助手通过 hive-resource 取得和续期GPU租约，与视频共用GPU时拒绝同轮视频生成，可先完成文字再手动生成。

内置方法包括完整叙事与跨镜状态控制，以及实际本地 H3 skill、Ref2VA 官方参考与项目规则正文；每轮保存读取方法的版本／内容哈希。项目上下文直接取当前持久化完整剧本与有序拍摄本，实体索引可进一步读取完整公开资料。参考图由项目资产ID读取并校验哈希；候选观察提供首／中／尾三帧及具体时间点，不能证明完整运动、声音、口型或视觉质量。

助手只调用明确工具，没有终端、任意文件、全局配置、任意网络或 Reference 写权限；允许读取限定的短片程序文件并提出修订，采用前由界面执行回归验证。文本及视频提交使用与网页相同的生成函数和既有校验。修订提案不可变，来源revision变化后不可采用；提案自身检查字段、引用、对白、词数与待定问题，过期的当前项目另行检查，避免形成不能采用新空间的循环。采用保留完整前后创作版本及审计。

会话、消息、工具动作、方法哈希、观察来源、工作流和候选ID保存在SQLite。页面轮询显示回复和操作记录；刷新可续读。每项目可开独立对话，一会话一轮、总并发两轮、每轮10分钟及48次工具调用上限。取消助手不取消已经提交的独立生成；重启将未完成助手标为中断，保留历史，不自动再调用模型或再次生成。请求ID支持幂等重试，同ID不同内容拒绝。

运行助手边界检查：`node --test server/film-agent.test.mjs`。SDK shrinkwrap 中的 brace-expansion 用 postinstall 固定补丁到5.0.12；安装脚本与锁文件一并交付。完整验收证据见 [Agent 接入记录](AGENT_WORKFLOW.md)。

### [Sean] 工作流改进与调试交付

制作助手新增「工作流方法」「程序修订」「诊断日志」三个折叠入口。用户判断图片/视频效果，默认不自动审片。项目与应用方法版本同时供 Agent 和固定 LLM 使用；提案采用后作用于后续生成。源码提案先显示差异，回归验证通过才写入，需重启短片应用生效。完整操作、持久化与恢复契约见 [工作流改进与调试](WORKFLOW_IMPROVEMENT.md)。
